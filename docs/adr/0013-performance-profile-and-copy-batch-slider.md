# 性能设置收口为三档预设与独立复制批次滑杆

将设置页「性能」分区的 4 个底层滑杆收口为两项：**性能档位**（`low` / `standard` / `high` 三档预设，打包目录读取并发、机台扫描分批、复制并发）与独立保留的**每批复制文件**滑杆（范围 5–20、默认 5、步长 5）。

## Considered Options

1. **保持 4 个独立滑杆**：现场操作员难以分辨「同时读取目录 / 每批扫描机台 / 同时复制文件 / 每批复制文件」的差异，容易调出互相制约或触发共享盘冲突的组合。
2. **全部收口为单一三档预设**：最简洁，但无法按现场网络与图片体积独立微调复制批次粒度。
3. **只保留扫描并发与复制并发两个滑杆**：仍要求普通用户理解并发数字，且未覆盖复制分批需求。
4. **三档性能档位 + 独立「每批复制文件」滑杆（采用）**：普通用户只需按网络与电脑负载在 `低负载 (2/1/3)`、`标准 (4/2/6)`、`高速 (6/3/10)` 之间切换，同时保留复制批次粒度的直观调节。

## Consequences

- 复制引擎保持按批硬推进语义（每批拷完再开下一批），因此实际同时复制文件数自然受限于 `min(档位复制并发, 每批复制文件)`；当 `每批复制文件` 为默认值 5 时，「标准」与「高速」档的实际复制并发封顶为 5，需调大至 10–20 才释放高档位并发，界面说明卡对此明确提示。
- `settings.json` 中的 `AppPreferences` 用 `performanceProfile` 取代原来的 `scanConcurrency` / `scanBatchSize` / `copyConcurrency` 三字段，避免磁盘出现无法映射到档位的数值组合；旧配置读盘时自动回落 `'standard'`。
- 四个底层环境变量（`QUICKFETCH_READ_CONCURRENCY`、`QUICKFETCH_MACHINE_BATCH`、`QUICKFETCH_COPY_CONCURRENCY`、`QUICKFETCH_COPY_BATCH`）继续保留作为运维应急覆盖通道；前三个部分生效时档位仍可切换（影响未接管项），全部生效时才禁用档位控件。
